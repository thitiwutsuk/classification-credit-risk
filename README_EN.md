# Credit Risk Analysis

This project analyzes bank customer data to answer: **what makes a customer "Credit Risky"**, and **how does a "Credit Worthy" customer behave**?

## Project Structure

```
.
├── analysis.py                     # end-to-end analysis script
├── requirements.txt                # required libraries
├── data/
│   ├── customer_data.csv           # customer data + label
│   ├── payment_data.csv            # payment history
│   └── dataset_description.md      # column-by-column description
└── output/                         # charts and summary tables generated by the script (created after running)
```

## Data

There are two data files in the `data/` folder (detailed column descriptions are in [`data/dataset_description.md`](data/dataset_description.md)):

| File | Description |
|---|---|
| `data/customer_data.csv` | Data for 1,125 customers. The `label` column marks whether a customer is risky (`1` = high risk, `0` = credit worthy), plus other demographic features (`fea_1` - `fea_11`) that are already numerically encoded |
| `data/payment_data.csv` | 8,250 rows of customer payment history (a customer can have multiple rows, since they may hold multiple credit products) — e.g. number of overdue payments, number of normal payments, credit limit, balance |

## What the Script Does

[`analysis.py`](analysis.py) follows a standard data-science workflow:

1. **Load & merge data** — summarize each customer's payment history (which spans multiple rows) down to one row per customer, then merge it with the demographic data
2. **Clean the data** — fill in missing values sensibly (e.g. no payment history recorded = fill with 0, unknown credit limit = fill with the median)
3. **Explore the data (EDA)** — compare the behavior of the risky group against the worthy group, both numerically and visually
4. **Build predictive models** — use Logistic Regression and Random Forest to rank which factors actually matter most (not just eyeballing it)
5. **Summarize in plain language** — turn the numbers and model results into readable answers to Q1 and Q2

## How to Run

Requires Python 3 (a virtual environment is recommended)

```bash
cd "classification credit risk"
pip install -r requirements.txt
python3 analysis.py
```

Once it finishes, you get:
- All results (statistics, model output) printed to the console
- 4 charts and a summary table saved to the `output/` folder

## Conclusion

### Q1: What makes a customer Credit Risky?

The main drivers of credit risk are **spending and payment behavior**, not demographic data:

- **High outstanding debt / balance** — risky customers have a `highest_balance` (highest balance on record) more than 2x higher on average than worthy customers
- **More frequent overdue payments** — the overdue ratio (`overdue_ratio`) and total overdue days are noticeably higher than the worthy group
- **Fewer on-time payments** — the number of normal payments (`pay_normal_sum`) is about 30% lower than the worthy group
- The encoded demographic features (`fea_1, fea_3, fea_5, fea_6, fea_7, fea_9`) show **very little** difference between the two groups compared to behavioral factors

**In short**: customers with high debt + frequent overdue payments + fewer on-time payments make up the core risky group

### Q2: How does a Credit Worthy customer behave?

Worthy customers show the opposite pattern of the risky group:

- **Keep debt/balance low** relative to their available credit limit
- **Rarely overdue** — the average overdue ratio is only around 3%
- **Pay consistently on time** — a clearly higher average number of normal payments than the risky group

**In short**: consistent on-time payment behavior and controlled debt are the signals of a credit-worthy customer

### Caveats

- The models achieve a ROC-AUC of about 0.68 (1.0 = perfect, 0.5 = random guessing), meaning they have some discriminative power but aren't highly accurate — the dataset is small (1,125 customers) and imbalanced (only 20% are risky)
- These results show **correlation**, not **causation** — e.g. a high balance could be both a cause and a consequence of risk at the same time. Treat this as a decision-support signal, not a definitive conclusion
